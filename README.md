## Running the application:

1. Clone the repository:
Windows:
```bash
git clone https://github.com/poppybun/the_commit_crew.git
```
Linux:
```bash
git clone git@github.com:poppybun/the_commit_crew.git
```
2. To run the project locally,</br>
2.1 Create .env.dev and .env.prod files in the root directory of the project. They should look like this:

.env.dev:
```bash
JWT_SECRET=<generate-a-real-random-jwt-secret-online-and-paste-here>
POSTGRES_DB=the-commit-crew-dev
AUTH_DB=auth_db-dev
POSTGRES_PASSWORD=<paste-db-password>
POSTGRES_PORT=5432
POSTGRES_HOST=db
ENVIRONMENT=dev

KAFKA_PORT=9094
KAFKA_UI_PORT=8090
ENGINE_MIN_DELAY=500ms
ENGINE_MAX_DELAY=2000ms
ENGINE_MAX_PRICE_IMPROVEMENT_BPS=50
```

.env.prod:
```bash
JWT_SECRET=<generate-a-real-random-jwt-secret-online-and-paste-here>
POSTGRES_DB=the-commit-crew-prod
AUTH_DB=auth_db-dev
POSTGRES_PASSWORD=<paste-db-password>
POSTGRES_PORT=5432
POSTGRES_HOST=db
ENVIRONMENT=dev

KAFKA_PORT=9094
KAFKA_UI_PORT=8090
ENGINE_MIN_DELAY=500ms
ENGINE_MAX_DELAY=2000ms
ENGINE_MAX_PRICE_IMPROVEMENT_BPS=50
```  

2.2 Run docker-compose:<br />
dev:
```bash 
docker-compose -p commitcrew-dev  --env-file .env.dev  up -d --build
```
prod:
```bash 
docker-compose -p commitcrew-prod --env-file .env.prod up -d --build
```
This starts all containers.

2.3. (Optional) Verify postgres: <br />
dev:
```bash
docker-compose -p commitcrew-dev  --env-file .env.dev  exec db psql -U postgres -d the-commit-crew-dev  -c "\dt"
```

prod:
```bash
docker-compose -p commitcrew-prod --env-file .env.prod exec db psql -U postgres -d the-commit-crew-prod -c "\dt"
```
You should see the list of tables for each database.

## Using auth:

The auth service provides REST endpoints for user registration, login, token refresh, and validation.

### OpenAPI Documentation

After running the app, access the interactive API documentation:

- **Swagger UI**: [http://your-linux-ip:3000/api/docs](http://your-linux-ip:3000/api/docs)
- **OpenAPI JSON**: [http://your-linux-ip:3000/api/docs.json](http://your-linux-ip:3000/api/docs.json)

The documentation is autogenerated and includes:
- All authentication endpoints (register, login, refresh, validate)
- Request/response schemas with validation rules
- Try-it-out functionality to test endpoints directly

### Usage

The auth service validates all inputs according to strict rules:
- **Username**: 3-30 characters (alphanumeric, underscores, hyphens)
- **Email**: Must be a valid email format
- **Password**: 8+ characters with uppercase, lowercase, number, and special character

1. **Register a new user:**
```bash
curl -X POST http://localhost:3000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "username": "john_doe",
    "email": "john@example.com",
    "password": "SecurePass123!"
  }'
```

2. **Login to get JWT token**
```bash
curl -X POST http://localhost:3000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"john_doe","password":"SecurePass123!"}'
```
  
3. **Use the token**
```bash
curl -X GET http://localhost:3000/api/auth/validate \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <your-access-token>" \
  -d '{"token":"<your-access-token>"}'
```

For testing, copy the access token and navigate to swagger:

[http://your-linux-ip:8081/swagger-ui/index.html#/]

Click the green Authorize button and paste your JWT token.

## Coding Conventions

### Naming 
- Classes: PascalCase (e.g. `UserService`)
- Methods/variables: camelCase (e.g. `isActive`)
- Constants: UPPER_SNAKE_CASE (e.g. `MAX_RETRY_ATTEMPTS`)
- Tables: lower_snake_case (e.g. `accounts_example`)

### Code Style
- Indent: 1 tab
- Line length: max 120 characters
- One class per file

### Git Workflow & Branch Protection
- **Develop branch**: All pushes require a pull request with 1 team member approval
- **Main branch**: Merges require 2 team member approvals before integration
- Follow Git flow: features branch from `develop`, releases branch from `develop`, hotfixes branch from `main`
